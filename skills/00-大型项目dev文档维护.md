# 大型项目dev文档维护
STATE ✓ 2026-11-22｜SCOPE 仅限工作区立项的大项目：开发告一段落后写/改单文件 `doc/dev.md`，只服务下一位 agent 接手｜SCRIPT 无（命令内联）

## 适用门槛
三条须同时满足，缺一不建、不改：
| 条件 | 判据 |
|---|---|
| 立项 | 工作区内有独立项目目录，且用户明确立项，或该项目已有 `doc/dev.md` |
| 仓库 | 项目目录自身是 git 仓库：`git -C <目录> rev-parse --show-toplevel` 输出该目录；挂在上层常用仓库里的不算 |
| 结构 | 多层或多子系统，有设计取舍需解释，会被反复接手 |

| 不满足时 | 处置 |
|---|---|
| 一次性脚本 / 小工具流 / 临时目录 | 不建 dev.md；结论进 memory，做法进 skill，设计意图写脚本头注释一两行 |
| 无自有仓库 | 不为写 dev.md 新建仓库，不把 dev.md 放进常用 git 区 |
| 未立项但 agent 觉得值得 | 不自主建；问用户是否立项 |

## 何时用
| 触发（先过「适用门槛」） | 动作 |
|---|---|
| 开发或重构完成要交接 / 写 dev.md / 下一位 agent 接手 / 读完 README 仍不知从哪改 | 按「骨架」写，按「校验」过 |
| 常量、路径、函数改名 / 新增或废弃机制 / dev.md 与代码对不上 | 按「更新」同批改 |
| 要知道另一个 agent 做过什么 | 不写 dev.md，读 `00-工作交接-执行轨迹` |
| 内容是进度 / 实测结论库 / 某件事怎么做 / 安装用法 | 分别进 taskbook / memory / skill / README |

## 取舍
| 写（代码里查不到） | 不写（一查就有） |
|---|---|
| 设计意图与理由；被名字误导的常量（如 `TIMEOUT` 是总预算非单次）；边界实测（数字 + 口径）；有意缺陷；多处联动；不可回退点；坑 | 函数签名与循环体；依赖版本（lock 文件有）；README 已有用法；变更史与过程复盘；行号 |

## 骨架
章节顺序 = 接手阅读顺序：先全局、再细节、末尾改与坑；无内容的章整章删，不留空标题。
```markdown
# 主题
STATE ✓ 日期｜SCOPE 一句边界（含不覆盖什么）
## 分层
| 层 | 负责 | 位置 |
## 位置与数据
## 常量
| 常量 | 值 | 作用 |
## <设计主题>   // 每个有取舍的机制一节：安全、压缩、重试…
| 项 | 值 | 理由 / 实测 |
## 主流程
## 函数
| 函数 | 职责 |
## 改哪验哪
| 要改 | 动哪里 |
## 约束
## 坑
| 现象 | 原因 | 处置 |
```

## 各章判据
| 章 | 判据 |
|---|---|
| 分层 | 缺一层的后果写明；扩能力改哪层写明 |
| 位置与数据 | 安装前后路径、运行期读写目录各一行；路径只在此章出现 |
| 常量 | 只列影响行为的；「作用」写它不是什么 |
| 设计主题 | 一行一决策：值 + 理由；有实测带数字与口径（如 0/3 vs 2/3）；有意缺陷标「有意设计」，防被当 bug 修回去 |
| 主流程 | 伪代码 ≤15 行，只留分支与状态变量，细节指向函数表 |
| 函数 | 一行职责，不贴签名；同族私有函数合并一行 |
| 改哪验哪 | 联动处写全（「三处联动」须列出三处）；不可回退点标明；验证命令可粘即跑，含反向断言（`assert not hasattr(...)`） |
| 约束 | 只收代码一眼看不出的运行约束；已在常量章的值不重写 |
| 坑 | 一坑一行；原因写到根因；处置写成动作 |

## 省 token
| 规则 | 值 |
|---|---|
| 单源 | 同一数字/路径/常量全文仅一处，他处用名字指代 |
| 形式 | 表优先，≤4 列，行 ≤240 字符；无散文、无导读、无结尾总结 |
| 符号 | 只用通用符号 `→` `>` `=` `🚫`，不自造，不设图例段 |
| 体量 | 软 12 KB / 硬 24 KB；超限按子系统拆 `dev-<子系统>.md`，主文件留分层与指针 |
| 指针 | `REF` 只挂一层 |

## 更新
| 触发 | 动作 |
|---|---|
| 改了常量 / 路径 / 函数名 | 同批改 dev.md 对应行，`STATE` 日期改为对照代码当日 |
| 新增机制 | 加一节设计主题：值 + 理由 + 实测 |
| 修掉一个坑 | 删该行，不留变更史；若含设计决策，转入设计主题 |
| 废弃机制 | 整节直接删，不留「已废弃」 |

## 校验
```bash
D=doc/dev.md; SRC=<主源码文件>
wc -c $D
grep -o '`[A-Za-z_][A-Za-z0-9_]*`' $D | tr -d '`' | sort -u | while read -r s; do grep -rqwF --exclude-dir=.git --exclude-dir=doc -e "$s" . || echo "MISS $s"; done
grep -oE '^[A-Z][A-Z_0-9]{3,} *=' $SRC | tr -d ' =' | while read -r c; do grep -qw -- "$c" $D || echo "UNDOC $c"; done
```
| 输出 | 含义 |
|---|---|
| `MISS x` | 文档里的标识符源码中不存在：改名漂移，或本就是文件名/术语（人工判） |
| `UNDOC x` | 源码全大写常量文档未提：判断是否影响行为，影响则补进常量章 |

脚本只验存在性，不验信息量。下列三条只能人工过：
| 人工门 | 判据 |
|---|---|
| no-op | 每句自问「删了接手者的行为会变吗」，不变即删 |
| 单源 | 同一数字 `grep -c` 只应命中一处 |
| 冷启动 | 只读 dev.md 能答出：改 X 动哪里、改完怎么验、哪里不能动 |

## 陷阱
| 现象 | 原因 | 处置 |
|---|---|---|
| `--exclude-dir` 不生效、grep 报找不到文件 | 选项写在 `--` 之后被当成文件名 | 选项放 `--` 前，模式用 `-e` 传 |
| `UNDOC` 把已写的常量报漏 | 用反引号匹配，而表里常量名常不带反引号 | 用 `grep -qw`，不依赖反引号 |
| 同一数字两章不一致 | 常量章与约束章各写一份 | 只留一处，另一处删行 |
| 数字被下一位 agent 当噪声 | 缺口径 | 补测量条件、样本量、版本 |
| dev.md 说 X、代码已是 Y | 改代码未同批改文档 | 提交前跑校验，改 `STATE` 日期 |
